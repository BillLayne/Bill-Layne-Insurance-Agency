# BLI Mail Gateway (v1.4)

One shared endpoint that lets **any** Bill Layne Insurance tool create a Gmail
draft or send an email directly from the program — no more copy-pasting HTML
into a Gmail compose window.

Bonus: emails sent through the gateway render **better** than pasted ones.
Pasting into Gmail strips the `<head>` styles and media queries; the gateway
delivers the raw HTML intact, so mobile-first templates keep their stacking
rules, Outlook VML conditionals, and Schema.org JSON-LD Rich Cards.

## Where it lives (since 2026-11-26)

**https://mail.billlayneinsurance.com/** is the Universal Sender. Mail Studio is `/studio.html`, Receipt Builder is `/receipt.html`.

The pages used to live at `www.billlayneinsurance.com/mail-gateway/`. There the key that sends email sat in browser storage that every page and every outside script on the public website could read. The new address serves nothing but these tools, under a policy that lets nothing else run (`tools/mail-site/site-rules.mjs`): only the pages' own script files, connections only to the Google script, no framing.

- **The files are still in this folder.** A small Cloudflare Worker (`tools/mail-site/`) serves them at the new address. **Pushing the repo does not deploy it.** Run `tools\deploy-mail-site.bat` (it runs the tests first).
- **The old address still answers.** On `www` the same pages load `moved.js` first, which passes every visitor on to the new address with the `#...` part intact (launcher files, hand-off links, the extension's receipt link). If that browser still holds a saved connection it offers one click to carry it across, once; the new page then asks before saving.
- **No inline script.** Each page's script is its own file (`sender.js`, `studio.js`, `receipt.js`). An inline `<script>` or an `onclick=` attribute would be blocked by the policy, and the tests fail on one.
- **The key box is masked text**, never `type="password"`, so password managers and autofill leave it alone.

## Three keys (gateway v1.4)

| Script property | Key | Can do | Where it belongs |
|---|---|---|---|
| `GATEWAY_SECRET` | **Full key** | ping, draft, send to anyone | Only `mail.billlayneinsurance.com` (and a tool whose Send button you really use) |
| `GATEWAY_DRAFT_SECRET` | **Draft-only key** | ping, draft. **Never send** | PDF Studio and every other tool |
| `GATEWAY_AGENCY_SECRET` | **Website key** | ping, send or draft **only to addresses at billlayneinsurance.com** | The website's own forms: the After an Accident report (`BLI_MAIL_GATEWAY_SECRET` in Cloudflare Pages) |

The two extra keys are optional. A gateway with only `GATEWAY_SECRET` behaves exactly as v1.3 did. An extra key is ignored unless it is at least 16 characters and different from the other keys. Every answer from the gateway carries `scope`: `full`, `draft` or `agency`.

**Changing the keys** (do this whenever a key may have been exposed): on the Universal Sender open **Settings → Change the keys**.
1. **Make three new keys.** They are made in the browser and shown once.
2. Paste them into **Script properties** in the Apps Script project.
3. **Test the keys.** The page pings with each one and only then switches this browser to the new full key.
4. Hand out the other two: **Connect PDF Studio** (opens PDF Studio with the draft-only key and asks there), **Copy the draft-only key** for other tools, **Copy the website key** then run `tools\SET-WEBSITE-MAIL-KEY.cmd`, which saves it in Cloudflare and rebuilds the website. **Check the After an Accident page** confirms it.

The old key stops working the moment `GATEWAY_SECRET` is saved, in every tool. Tools that still hold it answer "Unauthorized" until they get their new key.

## Loading a finished email into the Universal Sender

The sender page (`https://mail.billlayneinsurance.com/`) takes a finished email four ways. Nothing is created or sent until you click **Create Gmail Draft** or **Send Now**:

1. **1-Click `📋 Paste HTML from Clipboard`.** Reads your clipboard, auto-cleans toolbars, extracts the subject, collapses the raw code drawer, and renders the live preview.
2. **Drop or choose files (smart `.html` + `.pdf` routing).** Dragging an `.html` email file and up to 5 PDF attachments onto the window routes the `.html` to Step 1 and the PDFs directly to Step 3 Attachments.
3. **Hand-off link (`#z=`).** Open `https://mail.billlayneinsurance.com/#z=<payload>` (the old `…/mail-gateway/#z=` form is passed on) where the payload is `base64url( deflate-raw( JSON {v:1, name, subject, to, cc, html} ) )`. The fragment never leaves the browser, is scrubbed immediately via `history.replaceState`, and loads into the workbench.
4. **Setup link (`#gw=`).** Open `https://mail.billlayneinsurance.com/#gw=<base64url({u,s})>` to bring the Gateway URL + Secret to a new browser. Since 2026-11-26 the page **asks first** and saves nothing until you click **Yes, connect this browser** (see the safety rules below). Make the link with **Settings → Copy setup link**.

### Safety rules built into the pages (2026-11-26)

These came out of the 2026-11-26 audit. `tools\test-mail-gateway.bat` checks every one of them against stand-ins (nothing is sent, Google is never contacted). Run it after any change to this folder, to `tools/mail-site/`, or to `functions/api/accident-report.js`. It has three parts: `codegs.test.js` runs the real `Code.gs` in Node against fake Google services, `accident.test.mjs` runs the accident report function, and `smoke.js` drives the pages in Chrome under the real security headers. Set `MG_URL=http://127.0.0.1:8799` to run the pages against `wrangler dev` (start it with `--local-upstream 127.0.0.1:8799` so the Worker treats it as a local copy).

- **The secret only ever goes to Google.** Every page (`index.html`, `studio.html`, `receipt.html`, `gateway-client.js`, and PDF Studio) refuses to save, test or post to a Gateway URL that is not `https://script.google.com/macros/s/<id>/exec` (or the Workspace form `/a/macros/<domain>/s/<id>/exec`). A local address is accepted only while the page itself is running on `localhost` / `127.0.0.1`, for tests.
- **A setup link can never repoint the gateway on its own.** A `#gw=` link must carry **both** the URL and the secret, the URL must pass the rule above, and the page then shows a yellow question (`#setupAsk` with `#setupYes` / `#setupNo`). Nothing is saved, tested or sent until Yes. A link with only a URL used to keep the saved secret and post it to the new address; it is now ignored with a red note.
- **One customer's details never ride into the next email unnoticed.** When a new email is loaded (file, drop or clipboard paste):
  - if the email before it was already drafted or sent, **To / CC / Reply-To and the attachments are cleared** and a green note (`#carryNote`) lists what was cleared, with **Put them back (same customer)** (`#carryUndo`);
  - if it was not, they are kept, a yellow note asks **Yes, keep them** (`#carryKeep`) / **No, clear them** (`#carryClear`), and both Draft and Send are blocked until one is clicked.
  - An `.html` and its PDFs dropped together are one email: those PDFs stay. A `#z=` hand-off link always starts clean.
- **Send Now says exactly what is about to go.** The armed button names the recipient and counts the files. Sending the same email to the same address twice reads **"Already sent. Click again to send a SECOND copy"**. A timeout on Send says the email may still have gone out and to check Gmail Sent before trying again.
- **"Click again to draft anyway" works.** The pre-flight override is remembered per button, so the second click on the same button goes through and a click on the other button starts over.

**Automation note:** a script that drives this page should load the email first, then set To and attach files. If it reuses a tab and `#carryNote` shows the Keep / Clear question, click `#carryClear` before attaching.

### Automatic Cleaning & Pre-Flight QA (Client + Server `v1.3`)

Every route cleans and inspects the email before it reaches Gmail:
- **Preview toolbars removed:** `#bli-send-toolbar`, `#preview-toolbar`, browser extension overlays, and executable `<script>` tags are stripped (while **preserving** `<script type="application/ld+json">` Schema.org Gmail Rich Cards and Outlook VML namespaces).
- **600px spacer upgraded:** `data:image/png;base64,...` 600px anti-fit spacers become the hosted `img.billlayneinsurance.com` PNG (Gmail strips `data:` images from delivered mail).
- **Emoji-safe ASCII encoding:** Every code point above ASCII 126 is converted to a numeric entity (`&#xHEX;`) and astral chars are stripped from subjects so `GmailApp` never corrupts 4-byte emojis into ``.
- **Pre-Flight QA Bar:** Flags unfilled `{{TOKENS}}`, Cloudflare `cdn-cgi/l/email-protection` mangling, legacy Imgur links, and `>102 KB` Gmail clipping before you draft or send.

## One-time deploy (about 3 minutes)

> Do this while logged in as **Bill@billlayneinsurance.com** — the deploying
> account is the account the emails come from.

1. Go to **script.google.com** → **New project**. Name it `BLI Mail Gateway`.
2. Delete the starter code, paste the entire contents of `Code.gs`, and Save.
3. Click the **gear icon (Project Settings)** → **Script properties** →
   **Add script property**:
   - Property: `GATEWAY_SECRET`
   - Value: your secret (long and random)
4. Back in the editor, pick **`selfTest`** in the function dropdown → **Run**.
   Authorize when prompted (Advanced → *Go to BLI Mail Gateway (unsafe)* →
   Allow). Check Gmail → Drafts for the self-test draft.
5. **Deploy → New deployment** → type **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**  ← must be *Anyone*, NOT "Anyone with Google account"
6. Copy the **Web app URL** (ends in `/exec`).
7. Open `https://mail.billlayneinsurance.com/`, paste the URL + secret in **Gateway settings**, and click **Save & Test** — the header badge verifies both the URL and secret and shows your remaining daily sends.

### Updating the gateway (`v1.3` → `v1.4`)

Edit the code in `script.google.com`, Save, then **Deploy → Manage deployments →
pencil icon → Version: New version → Deploy**. The `/exec` URL stays the same!
(Never choose *New deployment*, which mints a new URL.)

## API reference (`v1.4`)

`POST` to the `/exec` URL. Body = JSON **string**, sent with
`Content-Type: text/plain;charset=utf-8` (avoids CORS preflight — never use `application/json`).

| Field | Required | Notes |
|---|---|---|
| `secret` | yes | One of the three keys (see **Three keys**; also accepted via `?secret=`). The draft-only key is refused for `send`; the website key is refused for any recipient outside `billlayneinsurance.com` |
| `mode` | no | `draft` (default), `send`, or `ping` (verifies secret + returns quota) |
| `to` | send: yes / draft: no | Comma-separate multiple addresses |
| `subject` | no | Defaults to `(no subject)` |
| `html` | draft/send: yes | Full `<!DOCTYPE html>…</html>` document |
| `text` | no | Plain-text part; auto-generated if omitted |
| `cc` | no | |
| `bcc` | no | Omit field → defaults to `Save@BillLayneInsurance.com`; send `""` → no BCC |
| `replyTo` | no | |
| `fromName` | no | Display name; defaults to `Bill Layne Insurance` |
| `attachments` | no | Up to 5 `{ name, mimeType, dataB64 }` items (`<= 20 MB` total) |

Success: `{ ok:true, mode, version, scope, draftId?, messageId?, attached, senderEmail, remainingQuota }`  
Failure: `{ ok:false, error }`
